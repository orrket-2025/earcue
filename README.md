# EarCue · 이어큐

발표자가 대본을 외우지 않아도 되도록, 대본을 한 문장씩 이어폰으로 미리 읽어주는 발표 프롬프터입니다.
프레젠테이션용 블루투스 리모컨의 방향 버튼으로 다음·이전 문장을 넘기고, 읽기 속도는 1×~5×까지 조절합니다.

현재 단계: **웹앱 프로토타입 (PWA)**. 최종 목표는 안드로이드 앱입니다.

## 폴더

| 파일 | 역할 |
| --- | --- |
| `earcue/index.html` | 앱 전체 (화면, 스타일, 로직이 한 파일에 있음) |
| `earcue/sw.js` | 서비스 워커. 앱 파일·폰트를 캐시해 오프라인에서도 열리게 함 |
| `earcue/manifest.json`, `icon*.svg` | 홈 화면에 설치할 때 쓰는 PWA 메타데이터 |
| `earcue/샘플대본.txt` | 업로드 테스트용 샘플 대본 |
| `.claude/launch.json` | 로컬 미리보기 서버 설정 |

## 배포 주소

**https://orrket-2025.github.io/earcue/** (GitHub Pages)

`main` 브랜치에 푸시하면 워크플로가 `earcue/` 폴더를 `gh-pages` 브랜치로 올려 자동 배포됩니다. 반영까지 1~2분 걸립니다.

## 로컬에서 실행

```bash
cd earcue && python3 -m http.server 8765
```

브라우저에서 `http://localhost:8765` 를 엽니다. 휴대폰에서 같은 와이파이로 접속하려면 `http://<맥 IP>:8765`.
음성 인식(말 인식)은 HTTPS 또는 localhost에서만 동작합니다. 휴대폰에서 시험하려면 HTTPS 호스팅(예: GitHub Pages, Netlify, Vercel)에 올리는 것이 가장 쉽습니다. 폴더를 그대로 올리면 됩니다.

## 사용 흐름

1. **대본 가져오기** — TXT, MD, DOCX 파일을 올리거나 텍스트를 붙여넣습니다. 앱이 마침표·물음표·느낌표·줄바꿈 기준으로 문장을 나눕니다.
2. **편집** — 문장을 누르면 도구가 나타납니다. `커서에서 나누기`, `다음과 합치기`, `듣기`, 삭제. `전체 다시 나누기`는 자동 분할을 다시 실행합니다.
3. **발표** — 큰 글씨로 현재 문장(빨간 LED), 다음 문장(초록 LED)을 보여주고, 버튼이나 리모컨으로 진행합니다.
   - `다음` : 다음 문장 읽기 · `이전` : 이전 문장 다시 읽기 · `읽기` : 현재 문장 읽기
   - 노브 : 읽기 속도 1×~5× (드래그, 휠, +/−, 키보드 화살표). 2×까지는 0.05 단위, 그 위는 0.25 단위
   - **자동 진행** 스위치 : 이어폰이 N×로 읽어준 시간에서 실제 말하기 시간을 추정하고, "말 끝나기 n초 전"에 다음 문장을 자동으로 들려줍니다. n초는 설정(톱니바퀴)에서 조절.
   - **말 인식** 스위치 : 이어폰 마이크로 발표자의 말을 듣다가 현재 문장의 끝부분이 들리면 자동으로 다음 문장을 읽습니다. 끄고 켤 수 있습니다.
4. **내 목소리 녹음** — 편집 화면의 "내 목소리 녹음"에서 문장을 하나씩 직접 읽어 녹음합니다. 가운데 버튼(또는 리모컨 읽기 버튼)으로 녹음 시작·정지, 정지하면 저장되고 다음 문장으로 넘어갑니다. 녹음은 기기 안(IndexedDB)에 저장되며, 발표 때 TTS 대신 재생됩니다. 속도 노브는 음높이를 유지한 채 재생 속도에 적용됩니다. 녹음이 없는 문장은 기기 음성으로 대체합니다. 문장을 나누거나 합치면 해당 녹음은 지워집니다.
5. **AI 목소리로 만들기 (ElevenLabs)** — 편집 화면의 "AI 목소리로 만들기"에서 본인의 ElevenLabs API 키를 입력합니다(키는 기기 브라우저에만 저장, ElevenLabs로만 전송). 직접 녹음한 문장(30초 이상, 60초 권장)을 샘플로 내 목소리를 복제하거나 계정의 기존 목소리를 선택하고, 말투 프리셋(차분한 강연 / 힘 있는 연설 / 친근한 발표 / 내 녹음 그대로)을 고른 뒤 "N문장 생성"을 누르면 문장별 음성이 만들어져 기기에 저장됩니다. 모델은 `eleven_multilingual_v2`, 글자 수만큼 크레딧이 듭니다. 문장을 고치면 해당 문장만 "다시 생성"으로 표시됩니다. 특정 인물의 목소리 복제는 지원하지 않습니다.
6. **설정 시트** — 음성 소스(내 목소리 / 기기 음성), 기기 음성 목소리 선택, 미리 듣기, 자동 진행 시점, 리모컨 버튼 배우기.

## 리모컨 연결

시중 프레젠테이션 리모컨은 대부분 블루투스 **키보드**로 동작합니다. 휴대폰의 블루투스 설정에서 페어링하면 앱이 키 입력을 받습니다.

기본 매핑: `PageDown / → / ↓ / Space` = 다음, `PageUp / ← / ↑` = 이전, `F5 / . / Enter / B` = 읽기.
리모컨마다 보내는 키가 다르므로, 설정 시트의 **버튼 배우기**로 실제 버튼을 눌러 등록하면 됩니다. 발표 화면 오른쪽 위 키캡에 마지막으로 받은 신호가 표시됩니다.

## 오프라인

대본은 기기 안(localStorage)에만 저장됩니다. 한 번 접속한 뒤에는 서비스 워커가 앱과 폰트를 캐시하므로 인터넷 없이도 발표 화면을 쓸 수 있습니다.
음성 합성은 기기에 설치된 TTS 엔진(안드로이드: Google TTS 등)을 쓰므로 오프라인에서도 됩니다. 단, **말 인식**은 브라우저의 음성 인식 서버를 쓰므로 인터넷이 필요합니다(안드로이드 앱 단계에서 온디바이스 인식으로 교체 예정).

## 읽기가 중간에 끊길 때

- 안드로이드에서 **말 인식**이 켜져 있으면 인식기가 마이크를 잡을 때 블루투스가 통화 모드로 바뀌며 재생이 끊길 수 있습니다. 앱은 TTS가 읽는 동안 인식기를 멈추고 읽기가 끝난 뒤 다시 켭니다. 그래도 끊기면 말 인식을 끄고 비교해 보세요.
- 발표 화면 상태 줄에 `읽기 중단: interrupted` 같은 원인이 표시됩니다. 피드백을 줄 때 이 문구를 함께 알려주면 원인 파악이 빠릅니다.
- 이어폰의 절전 기능(일정 시간 무음이면 연결 해제)이 있으면 첫 음절이 잘릴 수 있습니다.

## 알려진 한계 (프로토타입)

- 브라우저 TTS는 문장 하나를 다 읽어야 다음을 시작할 수 있어, 자동 진행에서 두 문장이 겹쳐 재생되지는 않습니다.
- 실제 말하기 시간은 추정치입니다. 몇 문장 지나면 읽기 속도 측정치가 보정되어 정확해집니다.
- DOCX 읽기는 라이브러리를 인터넷에서 불러오므로 온라인에서만 됩니다. PDF는 아직 지원하지 않습니다.
- 브라우저는 볼륨 버튼 등 미디어 키를 받지 못합니다. 그런 키만 보내는 리모컨은 안드로이드 앱 단계에서 지원합니다.

## 안드로이드 앱으로 가는 길

1. 이 PWA를 HTTPS에 올리고 **TWA(Trusted Web Activity)** 또는 **Capacitor**로 감싸면 Play 스토어용 APK/AAB를 만들 수 있습니다. 화면과 로직은 그대로 재사용합니다.
2. 네이티브 단계에서 바꿀 것: 안드로이드 `TextToSpeech` API(오프라인, 속도 제어 정밀), `SpeechRecognizer` 온디바이스 인식, 미디어 키·볼륨 키 수신, 화면 꺼진 상태에서도 동작하는 포그라운드 서비스, 블루투스 HID 장치 목록 표시.
